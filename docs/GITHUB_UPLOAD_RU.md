# Запуск и публикация DataBridge

## На компьютере

Выполни команды из раздела Run locally в README. Открой `http://127.0.0.1:3300` и нажми **Try the demo**. Демо хранит данные в памяти: при перезапуске вернутся начальные примеры.

## Как попробовать

1. Скачай Sample CSV на главной странице.
2. Нажми New import и загрузи файл.
3. Сопоставь колонки и нажми Validate file.
4. Посмотри: корректные строки, повторы и ошибки отмечены отдельно.
5. Нажми Commit valid rows и открой Record catalog.
6. Error report скачивает ошибки. Исправь исходный файл и загрузи его ещё раз.

## Репозиторий

Если нужно загрузить исходники вручную, создай пустой репозиторий `DataBridge` в GitHub. Не добавляй README через интерфейс: файл уже есть.

```sh
git init -b main
git add .
git commit -m "Build DataBridge ingestion and data quality workspace"
git remote add origin https://github.com/mileevskiyy/DataBridge.git
git push -u origin main
```

Не загружай `.venv`, `node_modules`, `.env`, `data` и локальные базы. Они исключены в `.gitignore`. Actions запускает проверки Python, сборку интерфейса и сценарий в браузере.

## Бесплатная демка в Render

Создай Docker Web Service из репозитория. Выбери Free, ветку main и Dockerfile в корне. Для демки отдельная база не нужна.

Переменные: `PUBLIC_DEMO=true`, `SEED_DEMO=true`, `HOST=0.0.0.0`, `PORT=10000`, `COOKIE_SECURE=true`. Не задавай постоянный `DATABASE_PATH`. После деплоя ссылку можно отправлять другу: кнопка Try the demo открывает общий демонстрационный набор данных без пароля.

Данные общие для посетителей и исчезают после перезапуска. Бесплатный сервис может засыпать и требовать времени на первый запуск. Реальные личные данные в публичную демку не загружай.
